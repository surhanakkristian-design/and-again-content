# Phase 1b data format (v1) — authoritative

Three kinds of data: a GLOBAL synonym table, a mistake library PER TOPIC, and a SHORT annotation per sentence.
The phone matches patterns (no expansion into rows).

## 1. Synonym table — `synonyms/*.json` (all files are merged; `table.json` = main)

```json
{"groups":[
 {"id":"someone","kind":"safe","pos":"x","m":["someone","somebody"]},
 {"id":"toward","kind":"safe","pos":"x","m":["toward","towards"]},
 {"id":"lift_raise","kind":"contextual","pos":"v","m":["lift","raise"],
  "ok":"She lifted her eyes. = She raised her eyes.","bad":"They raised money for charity. ≠ They lifted money for charity."},
 {"id":"swim_away","kind":"contextual","pos":"v","m":["swim away","swim off","scatter"],"head":0, "ok":"…","bad":"…"},
 {"id":"go","kind":"contextual","pos":"v","m":["go","leave"],"irr":{"go":["goes","went","gone","going"]},"ok":"…","bad":"…"}
]}
```
- `kind: safe` = interchangeable in EVERY English sentence. Applied automatically everywhere outside locked spans. Strict and short (~30 groups; do not grow it).
- Decision (Phase 1c, 18.9.2026): `have to / have got to` is NOT safe and stays out of the table as a safe group. The table author's reasoning is accepted (the swap breaks in "will have got to", "don't have got to", and must/have to is practised grammar); the original brief's example listing it as safe was wrong.
- `kind: contextual` = only where a sentence annotation allows it (`s` below). Needs `ok` (valid example) and `bad` (invalid example).
- `m` = members as LEMMAS (base form; multi-word allowed). `pos`: `v` verb, `n` noun, `a` adjective/adverb with -er/-est, `x` invariant.
- Inflection: forms are generated at build time (`synonyms/forms.json`): v → base, 3sg, past, past participle, -ing; n → singular, plural; a → base, comparative, superlative. Regular forms are generated by rule and kept only if they exist in `wordlist/en_words.txt`; irregular forms are given in `irr` as [3sg, past, pp, ing] for verbs, [plural] for nouns, [comparative, superlative] for adjectives. Multi-word members inflect the word at index `head` (default 0 for verbs, last word for nouns).
- A swap keeps the FORM: "lifted" (past) may become "raised" (past), never "raise".

## 2. Mistake library — `mistakes/<type_id>.json`

```json
{"type_id":39,"topic":"1. Conditional","level":"B1","items":[
 {"id":"39.01","kind":"will in the if-clause","verdict":"wrong",
  "pattern":"future 'will + verb' used after if instead of Present Simple",
  "slots":["right","wrong"],
  "sk":"Po „if“ patrí v First Conditional Present Simple: „{right}“, nie „{wrong}“.",
  "cz":"Po „if“ patří ve First Conditional Present Simple: „{right}“, ne „{wrong}“.",
  "en":"After “if”, First Conditional uses Present Simple: “{right}”, not “{wrong}”."}
]}
```
- ~20 items per topic. `verdict`: `wrong` or `correct_with_tip` (correct grammar and same meaning but not the practised structure, or a clearly more natural wording).
- `{right}` = the text the mistake replaced (filled automatically from the matched variant), `{wrong}` = the learner's wrong text (filled automatically). Any other slot (e.g. `{base}`, `{participle}`) must be supplied per sentence.
- Feedback rules (Phase 1): only what is wrong, no praise, English tense names (Present Simple, Past Perfect, past participle…), gender-neutral wording (no gendered Slovak/Czech past-tense forms addressed to the learner), never the whole reference sentence, ≤150 characters after filling. `en` is shown only at B1/B2 to non-sk/cz learners; write it for every item anyway.

## 3. Per-sentence annotation — `annotated/<exercise_id>.json` (SHORT — this is the token budget)

```json
{"id":10860,"t":44,"lv":"B1",
 "v":["The officer who stamped his passport barely raised her eyes.",
      "The officer that stamped his passport barely raised her eyes."],
 "lk":["who stamped","that stamped"],
 "s":{"raised":"lift_raise","barely":"barely_hardly"},
 "g":[["his"],["her"]],
 "o":{},
 "d":{"The":"A"},
 "p":["+even","-barely"],
 "m":[["44.01","which stamped"],["44.03","who he stamped"],["44.07","stamped","who stamped"]]}
```
Keys (omit a key when empty):
- `v` — `v[0]` is the reference exactly as given; at most 3 more variants, each STRUCTURALLY different (another construction or word order). Never a variant that is only a synonym/determiner/pronoun/optional-word swap of another one — those are what `s`/`d`/`g`/`o`/`p` are for.
- `lk` — the LOCKED span per variant (same order as `v`): the practised grammar = the exercise's answer span and its counterpart. Must occur verbatim in that variant. Discontinuous: pieces joined with ` .. ` ("would .. have been"). No other rule may change text inside a locked span; safe synonyms are not applied there either.
- Anchors (`s`, `g`, `o`, `d`, `p` minus-entries, `m` third element): a word or phrase that occurs in the variants, matched case-insensitively on word boundaries; `word#2` = second occurrence. An annotation applies in every variant that contains its anchor. An anchor must not lie inside a locked span.
- `s` — anchor → contextual group id: here that word may be any member of the group in the same form.
- `g` — gender chains: each inner list is a set of anchors that switch together masculine↔feminine (he↔she, him↔her, his↔her, himself↔herself). Only when the native sentence does NOT fix the gender (e.g. SK "tlačí", no pronoun, no gendered past form). Omit when it is fixed.
- `o` — single pronoun alternatives: anchor → "her|it" (SK "ju", thing or person), "him|it" (SK "ho"), "them|it" …
- `d` — determiner freedom where the native sentence has no article/demonstrative: anchor → code or explicit list. `A` = the|a/an|this|that, `P` = the|these|those|∅ (plural), `Z` = the|∅, or explicit "the|her|his".
- `p` — small optional words: `+w` may be inserted anywhere outside the locked span (at most once), `+w@anchor` only right after anchor, `-anchor` may be dropped. Multi-word allowed ("+of them", "-for"). Only meaning-neutral words (already, just, even, ever, really, up, of them, at all, for, then, so …).
- `m` — applicable library mistakes: `[libId, wrongText]` replaces the locked span in every variant; `[libId, wrongText, anchor]` replaces the anchor text instead; optional 4th element `{slot:value}` for extra template slots. The resulting wrong sentence is matched with the same freedoms (s/g/o/d/p). `[libId, "=full wrong sentence"]` when a replacement cannot express it.
- `ng` (annotators only, rare) — a proposed NEW contextual group when no table group fits: `{"ng0":{"pos":"v","m":["stapled","clipped"],"ok":"…","bad":"…"}}`, referenced from `s` as "ng0". Merged into `synonyms/annotator.json` by script.

## 4. Checker order (unchanged from Phase 1 except matching)
Phase 1c (checker v2 patches): BrE/AmE spellings are read as the pattern's token in steps 1b–4 (a normal substitution, not only
the sole difference); number words the learner typed are shown as typed in tips (never "1"); a multi-form verb anchor ("cut",
"dropped") takes one form from the words before it (pp after have/be/get, base after to/modals/do, else base+past); "her" flipped
to masculine is "his" before a word, "him" before a non-noun or after give/show/tell/let/make/… — never both.

normalise (lib/typedAnswer + Phase 1 §3.2 additions) → 1 match any variant with all freedoms → `correct`; 1b BrE/AmE → `correct`;
2 match any library mistake (variant with replaced span, same freedoms) → item verdict + filled feedback; 3 one typo on the best path
(Phase 1 exclusions: real word, word form) → `correct_with_tip`; 4 `wrong` + automatic tip from the CLOSEST path including every
freedom (never "write X instead of Y" when X is allowed). Feedback language: sk → sk, cz/cs → cz, others → en at B1/B2, null at A1/A2.
